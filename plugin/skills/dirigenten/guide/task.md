# Guide: task
Subject kind `task`. Call `act{on:{kind:"task",id}, action, rev, params?}`; the action must be in the envelope's `available`. States: open, closed, cancelled, delivered_outside, no_method.

Steps
1. `read{on:{kind:"task",id}}` and note `rev` and `available`.
2. Choose the primary action first, or the one that matches what the user asked.
3. Send `act` with that `rev`. If `written` is false, read again (the `rev` moved or the state changed) and decide again.
4. For ◐ ask once per task and day; for ■ call with the same on/action first, show the preview, and send `preview_id` and `user_approval` with the user's exact words, alone.
Missing facts do not stop a draft: write it with (?) where a fact is missing, save it with `act` action `run` and `params.text`, show it to the user and ask for a yes or corrections. Never show ids (t-2) or revisions (rev 1) to the user. Invent no facts: anything not given is (?). Events, visits, dates, prices and what the customer said come from a source: what the user said, the customer's mail or thread, the task's material or what dirigenten holds. Where there is no source, write (?) so the user fills it in. Never remove a (?) without the fact from a source, not even to get past the block on a send; ask for it in your single question about what is missing instead. When you fill a gap, save the text with `params.sources`, one row per gap with `value` and either `quote` (the user's words, verbatim, holding the value) or `ref` (the mail, material or node holding it); a gap dropped without a value is a row with `from: removed`, `reason: tas bort` and her words agreeing to drop it as `user_approval` on the same call (asked in your single question about what is missing); an outward send is shown only with its recipient list saved on it (`write_self` with `params.recipients`), so ask for recipients in that same question; without it no preview of what goes out is shown. A moment a person does, such as reviewing the tone, is marked done only with the user's own words as `user_approval`; never write yourself that it is done. Never send `user_approval` before the user has said yes to the very preview you showed. A claim that something happened, such as a visit, a call, a meeting or that the customer said something, is written only when a source says so; a polite phrase like «Tack för att vi fick titta på ert tak» is such a claim too. Before showing the preview, read your text sentence by sentence against the sources and replace every claim without a source with (?). Once the facts come, save the corrected text and show it in the same question as the preview, so one yes covers both. Do not mark the text done first: ask for the send's preview directly (`act` action `yes` on the send); it shows word for word everything that goes out, texts, images and recipients, and a yes on it marks those moments done too; a moment whose result is not shown in the preview needs its own yes; when another moment comes before the send, such as an image, a recipient list or another text, save its result too (a text with `act` action `run` and `params.text`, a file with `attach_file`) before asking for the preview, and if what you need is missing, such as the image, ask for it in the same question as the other missing facts; at most two questions in all, and the first one always shows the draft. A text changed after a yes needs a new yes before the moment is marked done.
A (?) stops only the send itself, what goes out to the customer. Anywhere else it is kept as an open question when the moment is marked done: say whom it concerns in `params.question_for` (else the customer); Ångra takes it away again. A moment that waits on another is still marked done outside (`done_outside`, ◐) with `reason` and `evidence`.
An unknown field in `params` (one the action does not list below) is refused before anything is written: `missing` names it and gives a template with the action's fields; nothing is dropped silently.
5. Tell the user what happened from `say`. To take it back: `act` with action `undo` takes back the last action (or send the action named as `inverse`).

Actions
- `start_task` — Starta uppdraget. Means: Uppdraget sätts i gång. Saknas något om kunden blir det frågor först. Not for: Inte för ett uppdrag som redan pågår. Severity: ● do directly. Inverse: none by design. From: open.
- `close` — Stäng. Means: Uppdraget är klart och stängs. Not for: Inte för uppdrag som ska avbrytas. Severity: ● do directly. Inverse: reopen. From: open.
- `reopen` — Öppna igen. Means: Uppdraget behöver arbetas vidare på. Not for: Inte för avbrutna uppdrag. Severity: ● do directly. Inverse: close. From: closed.
- `cancel` — Avbryt. Means: Uppdraget görs inte och läggs åt sidan. Not for: Inte för uppdrag som är klara. Severity: ◐ one yes per task and day. Inverse: uncancel. From: open, no_method.
- `uncancel` — Återta. Means: Uppdraget ska göras ändå. Not for: Inte för stängda uppdrag. Severity: ● do directly. Inverse: cancel. From: cancelled.
- `deliver_outside` — Levererat utanför. Means: Uppdraget är redan levererat utanför dirigenten. Not for: Inte för sådant som återstår. Severity: ● do directly. Inverse: undo_delivery. From: open, no_method.
- `undo_delivery` — Ångra levererat. Means: Leveransen utanför stämde inte. Not for: Inte för att öppna ett stängt uppdrag. Severity: ● do directly. Inverse: deliver_outside. From: delivered_outside.
- `take_method_update` — Ta in. Means: Uppdraget tar in den senaste versionen av arbetssättet. Påbörjade och klara moment ändras inte; gjort, ja och material följer med. Not for: Inte för att byta till ett annat arbetssätt. Severity: ◐ one yes per task and day. Inverse: none by design. From: open.
- `leave_method_update` — Låt vara. Means: Uppdraget fortsätter på den version det har. En nyare version erbjuds igen. Not for: Inte för att ta bort uppdragets egna ändringar. Severity: ● do directly. Inverse: leave_method_update. From: open.
- `undo_incoming` — Ångra. Means: Det som kom in med mejlet tas bort från uppdraget. Filen ligger kvar i banken. Not for: Inte för att svara på mejlet. Severity: ● do directly. Inverse: undo_incoming. From: open, closed, delivered_outside, no_method.
- `move_incoming` — Flytta. Means: Det som kom in med mejlet läggs på ett annat moment, eller på uppdraget utan moment. Not for: Inte för att koppla en ny fil. Severity: ◐ one yes per task and day. Inverse: move_incoming. From: open, closed, delivered_outside, no_method.
- `link_material` — Knyt till moment. Means: En sak i materialet läggs på ett av uppdragets moment, som underlag eller resultat där. Not for: Inte för att flytta det som kom in med ett mejl; det är Flytta. Severity: ● do directly. Inverse: link_material. From: open, closed, delivered_outside, no_method.
- `reply_mail` — Svara. Means: Svaret går som svar i mejlets tråd, från din egen adress. Du ser mottagaren och texten ordagrant före ja:et. Not for: Inte för ett nytt mejl, och inte för att skicka något till flera i en bunt. Severity: ■ preview, then the user's verbatim yes, alone. Inverse: none. From: open, closed, delivered_outside, no_method.
- `approve` — Godkänn texten. Means: Du godkänner den senaste versionen av en text som inte hör till något moment. Not for: Inte för en text på ett moment; godkänn den där. Severity: ● do directly. Inverse: none by design. From: open, closed, delivered_outside, no_method.
- `add_moment_after` — Lägg till ett moment efter. Means: Ett nytt moment läggs in efter ett annat, bara i det här uppdraget. Det som byggde på momentet före bygger på det nya. Not for: Inte för att ändra metoden för alla uppdrag. Severity: ◐ one yes per task and day. Inverse: remove_added_moment. From: open.
- `remove_added_moment` — Ta bort det tillagda momentet. Means: Momentet som lades till i uppdraget tas bort igen, när inget är gjort på det. Not for: Inte för metodens egna moment; hoppa över dem i stället. Severity: ● do directly. Inverse: add_moment_after. From: open.
- `add_dependency` — Lägg till ett beroende. Means: Ett delmål får vänta på ett annat, bara i det här uppdraget. Du ser före ja:et vilka delmål som flyttas på kartan. Not for: Inte för att ändra metoden för alla uppdrag. Params: from, to. Severity: ◐ one yes per task and day. Inverse: remove_dependency. From: open.
- `remove_dependency` — Ta bort beroendet. Means: Ett beroende som lades till i uppdraget tas bort, och delmålet behöver inte vänta längre. Not for: Inte för metodens egna beroenden. Params: from, to. Severity: ◐ one yes per task and day. Inverse: add_dependency. From: open.
- `add_milestone` — Lägg till ett delmål. Means: Ett nytt delmål läggs till, bara i det här uppdraget, med ett moment som en människa gör. Du ser före ja:et hur kartan ändras. Not for: Inte för ett resultat som biblioteket kan räkna fram; det är Låt uppdraget växa. Params: label, after?, before?, material?, responsible?, purpose?. Severity: ◐ one yes per task and day. Inverse: remove_added_milestone. From: open.
- `remove_added_milestone` — Ta bort det tillagda delmålet. Means: Delmålet som lades till i uppdraget tas bort igen, när inget är gjort på det. Not for: Inte för metodens egna delmål; hoppa över dem i stället. Severity: ● do directly. Inverse: add_milestone. From: open.
- `set_presentation_text` — Spara presentationens texter. Means: Presentationens rubrik, inledning eller beskrivningar sparas som nya versioner. De förra står kvar. Not for: Inte för leveranstexterna själva. Severity: ● do directly. Inverse: set_presentation_text. From: open, closed, delivered_outside, no_method, cancelled.
- `grow` — Låt uppdraget växa. Means: Ett resultat läggs till uppdragets mål, och delmålen som behövs för det läggs in. Du ser dem före ja:et. Not for: Inte för ett enda steg efter ett annat; det är Lägg till ett steg efter. Params: result. Severity: ◐ one yes per task and day. Inverse: grow. From: open.
- `report_time` — Rapportera tid. Means: Du skriver in tiden som lades, i timmar. Exempel: «Två timmar i dag.» Not for: Inte för att planera tid framåt; det är Lägg ett pass. Severity: ● do directly. Inverse: report_time. From: open, closed, delivered_outside, no_method, cancelled.
- `note_link` — Notera en koppling. Means: Du noterar att två saker i kundens system hänger ihop, och varför. Exempel: «Flödet skickar välkomstmejlet.» Not for: Inte för att ändra något i kundens system. Severity: ● do directly. Inverse: note_link. From: open, closed, delivered_outside, no_method, cancelled.
- `set_brief` — Spara briefen. Means: Uppdragets brief sparas: målet, mottagaren, omfattningen och datumen. Not for: Inte för att planera om uppdraget. Params: brief. Severity: ● do directly. Inverse: set_brief. From: open, closed, delivered_outside, no_method, cancelled.
- `run_quick` — Gör snabbt. Means: En snabbhandling körs för uppdraget, med förmågan och dess värden. Not for: Inte för att publicera; det görs på leveransens moment. Severity: ● do directly. Inverse: none by design. From: open, no_method.
- `change_method` — Byt metod. Means: Uppdraget följer en annan metod från nu. Not for: Inte för att ändra metoden för alla uppdrag. Severity: ◐ one yes per task and day. Inverse: none by design. From: open, no_method.

Example 1: `act{on:{kind:"task",id:"<id>"}, action:"start_task", rev:"<rev>"}` — Starta uppdraget: Uppdraget sätts i gång. Saknas något om kunden blir det frågor först.
Example 2: `act{on:{kind:"task",id:"<id>"}, action:"close", rev:"<rev>"}` (Stäng, inverse `reopen`) followed by `act{…, action:"undo", rev:"<new rev>"}` when the user changes their mind.
Counterexample: `start_task` while the task is "closed" is refused (Går inte nu: uppdraget är stängt. Det som går nu: Öppna igen.). Do not retry it; read and take what `available` offers.
Edge case: two people act on the same `rev`: one is written, the other gets `written:false` with the new `rev`. Read, then decide again. The `unavailable` list gives `why` and what unlocks it.
